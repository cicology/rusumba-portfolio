Tutor Vetting Automation

RoleEngineer
Client123tutors (EdTech platform)
Year2026
StatusIn production
KYC APIBiometricsAML ScreeningSupabaseNode.js

The project

Every tutor application was manually reviewed by an admin before going live, a human bottleneck that could not scale past roughly 50 applications a week, with no verifiable identity or background checks behind it. For a platform putting tutors in front of students, that is both a growth ceiling and a trust problem.

The work was to automate vetting end to end, without lowering the bar on who gets approved.

What I did

  • Built an automated vetting pipeline integrating a South African identity verification API (InTouch).
  • Wired in government ID verification, facial-match and liveness biometrics, AML/sanctions screening, and bank-account verification, running in parallel.
  • Built a tiered decision engine that auto-approves clean applications and flags edge cases for human review.
  • Cut the admin out of the happy path, leaving humans to handle only genuine exceptions.

Where it landed

Vetting time dropped from 2–5 business days to under 2 hours. Admin time per application fell from ~30 minutes to ~2 minutes on the review queue only, and the scalability ceiling is gone entirely.
